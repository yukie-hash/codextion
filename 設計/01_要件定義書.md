## 1. 目的・背景

### 1.1 目的
複数のスレッド（コーダー）が限られた共有資源（ドングル）を奪い合う状況をシミュレートし、
**デッドロック・飢餓・データ競合を起こさずに**資源を調停するプログラム `codexion` を作成する。

### 1.2 背景
「食事する哲学者問題」の変種。以下が追加されている。
- ドングル解放後の**クールダウン**
- 待ち行列の**調停ポリシー**（FIFO / EDF）
- **自作の優先度付きキュー（ヒープ）**の使用

### 1.3 学習上のゴール（本課題固有）
- pthread の mutex / 条件変数を使った同期の設計ができる
- デッドロックの成立条件（コフマンの4条件）を説明できる
- 相互評価で、全ての行を自分の言葉で説明できる

## 2. 用語定義

| 用語 | 意味 |
|---|---|
| コーダー | シミュレーションの主体。1コーダー＝1スレッド。番号は 1〜N |
| ドングル | コンパイルに必要な共有資源。コーダーと同数（N個）。隣り合うコーダー間に1つ |
| コンパイル | 左右2つのドングルを保持して行う動作。開始時刻が「最後のコンパイル開始時刻」になる |
| デバッグ / リファクタリング | ドングル不要の動作。コンパイル後にこの順で行う |
| バーンアウト | 最後のコンパイル開始（または開始時刻）から `time_to_burnout` ms 以内に次のコンパイルを開始できなかった状態 |
| クールダウン | ドングル解放後、`dongle_cooldown` ms の間そのドングルが取得不可になること |
| スケジューラ | 同じドングルを複数コーダーが要求したとき、誰に渡すかを決める規則 |
| FIFO | First In, First Out。要求した順に渡す |
| EDF | Earliest Deadline First。期限（`last_compile_start + time_to_burnout`）が早い順に渡す |
| モニター | コーダーとは独立したスレッド。終了条件（バーンアウト / 全員達成）を監視する |
| 飢餓（starvation） | 特定のコーダーがいつまでも資源を得られない状態 |

## 5. 機能要件

### FR-01 引数の受け付け
- プログラムは次の **8個の引数をすべて必須**で受け取る。
  ```
  ./codexion number_of_coders time_to_burnout time_to_compile time_to_debug \
             time_to_refactor number_of_compiles_required dongle_cooldown scheduler
  ```
- 詳細仕様は [7.1 入力仕様](#71-入力仕様コマンドライン引数) を参照。

### FR-02 入力検証
- 引数の個数が8でない場合はエラーとする。
- 数値引数が「負の数」「整数でない値（空文字・記号・小数・英字を含む）」「int の範囲外」の場合はエラーとする。
- `scheduler` が `fifo` / `edf` 以外の場合はエラーとする。
- エラー時はエラーメッセージを標準エラー出力に出し、**シミュレーションを開始せず**、非0で終了する。リークしないこと。

### FR-03 コーダーの生成
- コーダー1人につき1スレッドを `pthread_create` で生成する。
- 番号は 1〜`number_of_coders`。
- 配置は円形：コーダー1 はコーダー N の隣、コーダー k は k-1 と k+1 の間。

### FR-04 ドングルの配置
- ドングルは `number_of_coders` 個。隣り合うコーダーの間に1つずつ置く。
- 各コーダーは左右に1つずつドングルを持つ。
- **コーダーが1人のときはドングルも1つ**（左右が同じドングルになる）。

### FR-05 コーダーの行動サイクル
各コーダーは次のサイクルを繰り返す。各動作は排他的（同時に2つの動作をしない）。

1. 左右2つのドングルの取得を試みる（取得できるまで待つ）
2. 2つ揃ったら **コンパイル**（`time_to_compile` ms）。この間ドングルを保持し続ける
3. コンパイル終了後、両方のドングルを解放する
4. **デバッグ**（`time_to_debug` ms）
5. **リファクタリング**（`time_to_refactor` ms）
6. 直ちに 1 に戻る

### FR-06 ドングルの排他
- 1つのドングルを同時に2人以上が使用してはならない。
- ドングルの状態は mutex で保護する（課題指定）。

### FR-07 クールダウン
- ドングル解放後、`dongle_cooldown` ms が経過するまでそのドングルは取得できない。

### FR-08 調停（スケジューリング）
- 複数のコーダーが同じドングルを要求した場合、`scheduler` に従って渡す相手を決める。
  - `fifo`：先に要求したコーダーを優先
  - `edf`：`last_compile_start + time_to_burnout` が最も早いコーダーを優先
- **EDF では期限が同値の場合のタイブレーク規則を定め、決定論的に動作すること。**
- 調停には自作の優先度付きキュー（ヒープ）を使う（C-08）。

### FR-09 ライブネス
- パラメータが実現可能である限り、`edf` の下でコーダーが飢餓状態に陥ってはならない。
- いかなるパラメータでもデッドロックしてはならない。

### FR-10 モニター
- コーダーとは独立したモニタースレッドを1つ持つ。
- モニターはバーンアウトを検出し、シミュレーションを停止させる。

### FR-11 ログ出力
- コーダーの状態変化を標準出力に出す。形式は [7.2 出力仕様](#72-出力仕様ログ)。
- 1行の中で2つのメッセージが混ざってはならない（mutex でシリアライズ）。
- 各「is compiling」の前に、そのコーダーの「has taken a dongle」が2行出ること（1人の場合を除く）。

### FR-12 終了条件
シミュレーションは次のいずれかで停止する。
- (a) いずれかのコーダーがバーンアウトした → `burned out` を1行出して停止
- (b) 全コーダーが少なくとも `number_of_compiles_required` 回コンパイルした → 停止

停止後は次を満たす。
- 全スレッドが `pthread_join` で回収される（プログラムがハングしない）
- `burned out` の後に他のログが出ない
- 全ての mutex / cond が destroy され、全ての確保メモリが解放される

## 6. 非機能要件

| ID | 分類 | 要件 | 確認方法 |
|---|---|---|---|
| NFR-01 | 時間精度 | `burned out` は実際のバーンアウト時刻から **10ms 以内**に表示する | 短い `time_to_burnout` で実行し、期待時刻とログ時刻の差を測る |
| NFR-02 | 時間精度 | 各動作の所要時間は指定値から大きくずれない（目安：数ms以内） | ログのタイムスタンプ差分を確認 |
| NFR-03 | スレッド安全性 | データ競合がないこと | `valgrind --tool=helgrind`（または drd）でエラー0 |
| NFR-04 | メモリ | リークがないこと（正常終了・エラー終了の両方） | `valgrind --leak-check=full` で "definitely/indirectly lost: 0" |
| NFR-05 | 堅牢性 | 極端な入力（1人、200人、極短・極長時間）でクラッシュ・ハングしない | ストレステスト |
| NFR-06 | 保守性 | Norm 準拠。1ファイル1責務を目安に分割 | `norminette` でエラー0 |
| NFR-07 | CPU 使用 | 待機中にビジーループで CPU を浪費しない（cond_wait / timedwait を使う） | `top` で CPU 使用率を確認 |
| NFR-08 | 説明可能性 | 全ての行を作者が説明できる | 相互評価の練習 |

## 7. 入出力仕様

### 7.1 入力仕様（コマンドライン引数）

| 位置 | 名前 | 型 / 単位 | 許容範囲 | 意味 |
|---|---|---|---|---|
| 1 | `number_of_coders` | 整数 | 1 〜 INT_MAX ※1 | コーダー数＝ドングル数 |
| 2 | `time_to_burnout` | ms | 0 〜 INT_MAX | この時間内に次のコンパイルを開始しないとバーンアウト |
| 3 | `time_to_compile` | ms | 0 〜 INT_MAX | コンパイル時間 |
| 4 | `time_to_debug` | ms | 0 〜 INT_MAX | デバッグ時間 |
| 5 | `time_to_refactor` | ms | 0 〜 INT_MAX | リファクタリング時間 |
| 6 | `number_of_compiles_required` | 回 | 0 〜 INT_MAX ※2 | 全員がこの回数以上で正常停止 |
| 7 | `dongle_cooldown` | ms | 0 〜 INT_MAX | ドングル解放後の取得不可時間 |
| 8 | `scheduler` | 文字列 | `fifo` / `edf` のみ | 調停ポリシー |

- 数値は `[0-9]+` のみ受け付ける（先頭 `+`、空白、小数点は不可）。
- ※1 `number_of_coders = 0` はシミュレーションとして意味がないため**エラー**とする（本プロジェクトの決定。8章 D-01）。
- ※2 `number_of_compiles_required = 0` は「開始直後に全員達成」として即停止を許容する（D-02）。

### 7.2 出力仕様（ログ）

標準出力に、1イベント1行で次の形式を出す。

```
<timestamp_in_ms> <X> has taken a dongle
<timestamp_in_ms> <X> is compiling
<timestamp_in_ms> <X> is debugging
<timestamp_in_ms> <X> is refactoring
<timestamp_in_ms> <X> burned out
```

- `timestamp_in_ms`：シミュレーション開始からの経過ミリ秒（整数）
- `X`：コーダー番号（1始まり）
- タイムスタンプは行の出力順に非減少であること

### 7.3 エラー出力
- 標準エラー出力に `Error: <理由>` の形式で1行（末尾改行あり）。

### 7.4 終了コード

| 状況 | 終了コード |
|---|---|
| シミュレーションが停止した（バーンアウト・全員達成のどちらでも） | 0 |
| 引数エラー | 1 |
| 初期化失敗（malloc / pthread_create 等） | 1 |

## 8. 決定事項・未決事項

課題文が明示していない部分は、ここで**決めて記録**しておく（評価で聞かれたときの根拠になる）。

| ID | 論点 | 決定 | 理由 |
|---|---|---|---|
| D-01 | `number_of_coders = 0` | エラー | コーダーがいないシミュレーションは無意味。malloc(0) も避けられる |
| D-02 | `number_of_compiles_required = 0` | 即停止を許容 | 「全員が0回以上コンパイルした」は開始時点で真 |
| D-03 | 時間系の値 `0` | 許容 | 課題は「負の数」を拒否と言っており 0 は禁止していない |
| D-04 | EDF のタイブレーク | 期限が同じなら**コーダー番号が小さい方**を優先 | 決定論的で説明しやすい |
| D-05 | コーダー1人のとき | ドングルを1つ取って待ち、`time_to_burnout` 後にバーンアウト | ドングルが1つしかないのでコンパイル不可能 |
| D-06 | 達成済みコーダーのバーンアウト判定 | 規定回数を達成したコーダーはバーンアウト判定から外す | 達成済みスレッドは終了しており、コンパイルし続ける義務がない |
| D-07 | バーンアウトの判定式 | `now - last_compile_start > time_to_burnout` | 「以内に開始しなかった」＝超過したら燃え尽き |
| D-08 | 「has taken a dongle」の出力タイミング | 2つ同時に取得した後に2行連続で出す | 片方だけ取って待つ設計を採らないため（設計書 6章） |

| ID | 未決事項 | 期限 |
|---|---|---|
| U-01 | 停止時、`usleep` 中のコーダーをどこまで早く抜けさせるか（短い単位に分割するか） | Phase 8 |
| U-02 | 実現不可能なパラメータ（例：`burnout < compile + debug + refactor`）の扱い。現方針は「そのまま実行してバーンアウトさせる」 | 評価前 |
